改造單位：一個來源任務，衍生少量有用途的學習視圖

固定來源與 split → 審核任務及答案 → 選資料缺口 → 以實際 harness 產生輸入 → 收集學生行為與真實回饋 → Qwen 修正必要部分 → 獨立驗證 → 編譯 loss spans → 匯出版本化 learner view

原始 episode 保留來源、權利、root/group、split、工具 registry、來源證據、技能版本及私有驗證定位。衍生 view 另外記錄目標 tokenizer、chat template、policy、實際 prompt hash、可見來源、loss spans 與回饋 receipt hash。先按來源家族切分，再衍生所有 view；同題換語言、換數字、換 skill 表示或增加修復回合，都不能跨到另一個 split。

視圖模型要學的行為驗證與邊界
基本作答與無 skill保留語言、基本知識、逐字傳遞、單步計算、完整答案與終止符。避免學成沒有 skill 就拒答；測 bare 能力是否退步。
正確 skill／相似但不適用遵守前提，使用必要程序；不把沒有用到的技能強行套上。輸入不能含「正確技能」標記或 teacher 選擇理由。skill 重命名但程序不變時，行為應保持。
語義最小對比讀懂啟用／停用、先後次序、原始值／換算值、必填／選填、排序方向。改一個有意義條件就重驗 target；不能沿用原答案。不要只換實體名製造表面多樣性。
RAG 與干擾在相似實體、舊版本、否定敘述中找支持來源；無證據時標示缺口。引用位置正確與答案被支持分開驗證。隱藏答案、teacher 解答與驗收標記不能進檢索庫。
真實回饋修復保留已正確部分，根據實際錯誤修復；不改測試，不憑空報成功。錯誤輸出保留但不計 loss；修正版須過獨立驗收。公開測試通過仍不代表完整正確。
有來源的狀態交接延續已知值、待解問題、失敗與尚未執行的動作；壓縮時保留限定條件。從完整可追溯的實際歷史產生 state；不能把 teacher 才知道的答案當成 memory。
有限組合讓前一 skill 的具型別輸出符合下一 skill 的輸入，例如抽取→單位統一→計算。一個 skill 可完成時直接完成；保留缺輸入、不相容及中途失敗的案例。

增加 skill 利用率不等於每題放全部 64 個 skill。應衡量每個程序的適用、近似不適用、缺輸入、失敗恢復及跨情境遷移。基礎數學與工具語意目前最缺，可以優先新增有獨立來源及不同關係結構的樣本；同一成功 target 僅在語義與契約不變時才能重用。

目前 harness 能直接支援什麼，哪些還需要新介面

目前 barbet_inference 支援 MiniCPM／Qwen 原生模板。skill 由 host 按 output contract 選短卡，或由呼叫者明確指定完整技能；檢索、公開執行檢查及最多三次呼叫也由 host 控制。第一階段 SFT 應使用同一個實際渲染流程；prepare 可檢查初始 prompt，trace 可核對後續 prompt。

目前 repair feedback 被序列化為 user continuation。若資料自行改成 tool role，就不是相同介面。需保留原始 native tool token、thinking mode、停止標記、公開測試與來源選取；Barbet 則需要另外測試其 tokenizer／renderer／生成器 adapter，不能把 mini/qwen 後端當成 Barbet Attention/Mamba 支援證明。

模型自主 search_skills、load_skill 或反覆檢索，尚未在此 API 實作。若要訓練這些動作，先實作有真實回傳、錯誤與預算語義的 dispatcher，再生成對應資料。不能先教一組不存在的工具名稱，便宣稱 test time 可運作。

長上下文與 reasoning：把長度用在必要資訊上

較長 context 提供外部知識及工作空間，但小模型仍需學會選取、綁定、更新與忽略。先建立短且完整的工作區，再增加真實干擾、來源距離、依賴深度與狀態變更；這四個軸應分開控制。不能用重複文字填長度，也不能把更多生成 tokens 當成更強 reasoning。

既有固定權重實驗提供一個警訊：MiniCPM 的四領域平均由 38.02% 提升至 50.39%，但同 harness 的 Qwen 為 76.24%。盲目三輪自我檢查僅 38.54%，平均 output tokens 約 4,782；選定方案為約 1,944 tokens、1.19 次呼叫。程式的真實執行回饋則有用：同一批軌跡的前 1／2／3 次成功率為 55.73／64.06／66.41%。這支持優先教「使用外部可驗證回饋」，而非統一延長自言自語。完整定義與限制見固定權重報告。

長度視圖的工程起點可用目標 tokenizer 的 2K、4K、8K、16K 上限，這是待驗證的 heuristic。完整 task、schema、必要來源與 output reserve 超出預算時應拒絕匯出，不能偷偷截斷。MiniCPM、Qwen 與 Pangolin 的 token 數不可互換。

保留 canonical 1M 原件，短 learner view 另立版本。此提案沒有把 1M 規格取消或把短樣本偽裝成合格的 canonical 新資料。若正式採用短工作區，需要另行固定 export／recipe；保留父樣本 lineage、split、來源範圍及完整原件，審查抽取後是否仍含所有必要前提。真正測試 1M 能力時，仍需能處理該長度的實際模型後端、足額 output 預算及新 holdout。

訓練編譯項目必須保證
loss masking只監督核准 assistant targets 與所需終止符；skill、來源、user、tool／host 觀察、失敗與未核准輸出皆為 -100。
錯誤與修復錯誤可保留為後續修復的條件，但不正向訓練錯誤 token。沒有回饋的「再想一次」不能偽稱 execution feedback。
causal shift輸出的 labels 不預先 shift，由 trainer 恰好 shift 一次；檢查第一個 answer token、最後終止符與跨 turn 邊界。
token 邊界以實際 template／tokenizer 驗證，不僅用字元位置猜測；prefix 與 target 合併分詞不一致時停止輸出。
截斷／packing不得產生只剩答案前半段或沒有終止符的正樣本；維持現有不跨樣本 packing 契約。
成本與 normalization追蹤 input 與 supervised tokens、loss reduction 與梯度累積分母。全長 tokens 相同不等於有效監督量相同。

實驗要證明「SFT 讓模型更能從 harness 得益」

僅比較訓練前後總分，無法區分基本能力進步與 skill 利用率進步。每個候選 checkpoint 都需要下列四格，使用相同公開文件池、工具、task family 與固定策略；另做 token 與 latency 配額的比較。

bare同一 harness
訓練前 baseAB
新 SFT checkpointCD
訓練前的 harness 增益 = B − A
訓練後的 harness 增益 = D − C
skill 利用能力的交互增益 = (D − C) − (B − A)
同時要求 D > B，並守住 C 的基礎能力保留門檻。

不能靠把 C 訓壞而製造漂亮增益。pilot 的工程驗收原則是：D 對 B 的提升與交互增益都有正向統計證據，預先選定的語言、知識、指令與基本計算 retention 切片沒有超出退步容忍值。容忍值、統計 power、訓練 budget 與 checkpoint cadence 需在真正啟動前固定；本提案未冒稱已指定或完成訓練。

B2 是資料表示方案的整體比較；若有效，再各自移除 near-miss、counterfactual、RAG distractors，分辨內部成分的貢獻。不得把 B2 的整體提升歸因給其中一項。各組固定 base、來源家族庫、optimizer 與 supervised-token 預算，同時揭露總 input tokens／FLOPs 的差異。禁止為了假裝算力公平而偷偷刪除必要 context。

資料抽樣的初始 heuristic 是：20% 基本能力與指令、25% 數量關係與程式計算、25% 工具語意、20% 證據／RAG、10% 程式回饋及狀態。這是針對 v26 缺口的起始提案，並非論文最佳比例；按獨立來源家族與 supervised-token 曝光量監控，不按展開後的列數盲抽。修復與 near-miss 是跨家族視圖，不是另外再加一組比例。維持單一混合 SFT，逐步提高困難度而持續保留基礎題。

評估報告同時列出 pass@1、實際 selector 的 selected@K、oracle pass@K 上界、修復收益、把正確答案改壞的比例，以及工具語意、來源支持、格式與語義分開的準確率。更多候選中恰有一個正解，若部署時選不出來，就不能算已獲得效能。記錄每題 input／output tokens、呼叫數、延遲與顯存；固定 output-token 配額與固定 latency 是不同比較，分開報告。

所有已看過的 v26／MiniCPM 測試題保持 diagnosis-only。不把失敗答案搬入新 SFT，也不在舊 final test 上選新配方。建立新的來源家族 holdout，涵蓋未見 skill、工具 schema、組合與來源版本；同家族 paraphrase 不能跨 split。以來源家族做 paired cluster bootstrap，訓練資源允許時用多個 seed；少數工具模板的重複變形不能當成大量獨立證據。

這個方向的研究依據與適用限制

  • RAFT直接訓練模型在檢索文件中忽略干擾、使用支持證據。可借鑑其資料結構，但其領域內結果不證明 1B 在通用任務達到 9B。
  • Toolformer把何時呼叫、選 API、參數與結果使用納入學習；Self-RAG訓練按需檢索及判斷證據。後者主實驗為 7B／13B，且有自己的 reflection-token 協定，不能直接當作目前 runtime 已有功能。
  • GLM-5 §3.1描述將錯誤片段保留在軌跡中、但排除其 loss 的做法，支持修復資料的 masking 設計；是否同樣改善此 1B 模型仍須實驗。
  • VibeThinker-1.5B以多樣化 SFT 後接 RL 提升推理。可借鑑對解法覆蓋的重視，但不能把含 RL 的結果歸因於單獨 SFT，也不能用 oracle pass@K 代替實際系統成功率。
