# 給 Barbet 1B 的技能與公開解法

目標學生是使用者提供的 Barbet 1B Base。技能預先放入 context，模型依當前問題選用與組合程序，再產生答案或工具動作。資料應把必要的操作寫清楚，讓學生能根據前提、來源和中間結果跟著做。目前沒有測量 Barbet 的成功率、skill lift 或 1M accuracy。

## 說明應包含什麼

每個技能都要交代所需輸入、適用條件、具體操作、產出的值與檢查方法。把「分析問題」「組合技能」「確認正確」展開成有用的動作，例如辨認比例的分母、區分每面與每張紙、確認工具必填欄位、保留來源的「可能」與特定條件。

加入完整的通用教學範例，標明是虛構教學情境。範例應展示必要的公開計算或可觀察結果，與正在建置的來源題解答、gold patch、測試 oracle 分開。不要用來源中的真實實體承載未查核的科學敘述。

答案保留必要的輸入值、適用規則、中間計算或已觀測狀態、單位與結果。按照任務需要決定篇幅，不設通用的最短答案或固定行數。簡單分類題可以直接給分類；要求原因、比較或多步計算的題目，要回答完整要求。額外文字必須提供正確教學訊號。

## 輸出契約與技能組合

目前問題指定的輸出格式優先。要求 code-only、JSON 或 tool calls 時，保持該格式可解析與完整。將必要的程序說明放在 skill 中，不能把解說插入工具參數或破壞程式碼。工具結果由 executor 提供，後續回答依實際結果產生。

組合技能時，確認上一程序的輸出滿足下一程序的輸入與前提。缺少必要資訊時，說明缺什麼；能先完成的獨立步驟依契約處理。單一程序足以完成時直接使用。只公開任務需要的計算、狀態或簡短操作計畫，不匯出私有思維過程。

## 資料與生成成本

Barbet 資料建置維持單一混合 SFT。新樣本包含 1,000,000–1,048,576 個實際 Pangolin tokens，只有核准的 assistant outputs 計算 loss；來源、技能前文、user 和 tool observations 都 mask。既有 release 保持可重現。

降低教師成本可透過快取來源與技能 packets、批次選題及有限修復。學生需要的正確解說仍完整保留。長文件提供外部知識，技能提供可重用程序；不要把當前題目解答塞進技能，也不要用重複文字填長度。

## 維護與驗證

編輯 `skill.json`，讓每一步清楚交代「讀取什麼、做什麼、檢查什麼」。依 [CONTRIBUTING.md](../CONTRIBUTING.md) 更新版本與生成檔。技能應覆蓋適用、相似但不適用、缺輸入及失敗恢復案例。

數學用獨立計算、程式在已核准隔離環境測試、工具動作檢查 schema 和依賴、文件回答核對支持句與限定範圍。模型審稿保留真實 verdict；未通過者保持待修，不能只增加字數就宣稱品質提高。同一 Qwen 的作者與審稿回合不是人類驗證，也不證明 1B 學生能完成任務。

這份文件是資料與技能修訂指引。正式採用新的技能 catalog、recipe 或 renderer 時，先建立版本化提案、驗證來源與輸出契約，再固定新版本。GitHub 內容更新不會自動變更既有 HF 資料。

後續的 [skill-aware-sft-v1 提案](skill-aware-sft-v1.html) 根據 v26 的固定評測與公開候選資料，提出與實際 harness 一致的技能使用、RAG、語義對比及回饋修復視圖；[機器可讀規格](configs/skill-aware-sft-v1.json) 標記為尚未採用、尚未訓練。這份提案不變更上述 canonical 1M 樣本、單一混合 SFT、來源切分與既有 release 契約。短 learner views 需要另立 export／recipe 版本，不能當成已符合 canonical 長度的新資料。
