# 事實回答、來源與未知

`factual-question-resolution` v2 適用於穩定的可核實事實。`concept-explanation` v2 用於理解概念與機制；單憑「什麼是」「說明」不能決定適用性。`grounded-evidence-answer` v4 用於答案限定在可見來源的題目。這些文字提供程序，沒有加入真實地標答案，也不證明學生模型的幻覺已改善。

## 適用與相近的不適用情境

以下全部為虛構教學情境，不是來源題或模型評分資料。

| 請求 | 適用程序與可審核行為 |
| --- | --- |
| 何謂青塔的高度？ | 查詢特定實體的屬性；有可靠依據才回答，不能解釋完「高度」就當作完成。 |
| 何謂高度？ | 解釋概念；不需要猜測某座塔的數字。 |
| 來源說「青塔 21 層，不是 31 層；銀塔 31 層」。青塔是否 31 層？ | 依來源回答不是，青塔為 21 層。否定的數值與銀塔的數值都不能轉給青塔。 |
| 來源只記載銀塔樓層，問青塔樓層 | 明說來源未提及；不能借用銀塔的值。 |
| 來源稱青塔是「最動人的塔」，問青塔高度 | 主觀評語不支持高度，明說來源未提供。 |
| 今天青塔有幾位訪客？沒有工具或觀察結果 | 無法確認即時人數；讀過工具技能不表示執行過查詢。 |
| 翻譯「青塔有幾層？」 | 保持翻譯契約，不回答樓層問題。 |

## 資料改造與採用

同一事實可以建立來源在場與閉卷兩種視角，但需保留相同的來源根群組與既有 split。閉卷答案必須有獨立核對的依據，不能僅因教師生成流暢、引句連續或自評通過就當成世界事實。檢查實體、事件範圍、時間、屬性及否定；含指代的引句要有足夠上下文，主觀評語保留歸屬。

為不知道的問題建立拒答目標時，分清「不可觀測的即時狀態」「來源沒有提供」與「模型本身不會的穩定事實」。前兩者不證明模型對自身知識已校準。若依學生的回答建立已知／未知標籤，只能探測預留的 TRAIN 題，並對照獨立答案；不可用 DEV 或 TEST 回答製造訓練標籤。避免同一題、同一事實同時受到正解與無條件拒答的矛盾監督。

採用新版本時另固定 commit、完整 skill packet 雜湊、路由版本與資料清單；逐點重建前文、assistant loss mask 及 token 預算，不截斷技能。已開始的訓練與已發布資料維持原固定版本。新路由只能讀當前可見 messages 和 tools；正解、來源 ID、split 及分數不能決定 skill。

## 驗證方式與界線

先在 DEV 選定 checkpoint 與評分規則，再使用 TEST。比較同一題組、完整相同技能前文及實際部署精度，分別測量閉卷與來源在場；若測試新版 skill 前文的效果，另外固定權重進行比較，避免把前文變更與權重更新混為一談。

同時記錄正確回答、錯誤斷言、明確未知、無法判定，以及原本答對題目的保留率。全部拒答即使減少錯誤斷言也不能當作改善；無法判定不能一律算錯，也不能當作正確。答案含正確值但另有無依據斷言時，不應只以子字串命中認定正確。已知題數太少時擴充獨立核對的題組，不降低既定保留門檻。既有能力保留條件仍須驗證。

`python scripts/build.py --check` 檢查生成檔與路由邊界。這是軟體檢查，不是語義正確率、已知保留率、即時工具執行成功率或模型校準的證明。
