## Use When

當需要呼叫外部工具或API，且任務對參數格式、型別、順序或特定字串內容有嚴格規範時。

## Do Not Use When

當工具參數完全自由、無結構化要求，或任務未提供明確的註冊表定義時。

## Inputs

任務描述、工具註冊表（含參數定義、型別、必填/選填狀態）、原始資料或Payload、單位換算依據（若涉及）。

## Procedure

1. 依當下工具 schema 找出必要欄位，從可見資料逐一綁定實體、欄位與值。2. 區分來源與目的地、名稱與 ID，不能只因文字相近就替換。3. 嚴格保留 null、false、數值 0、字串 "0"、含前導零的 ID；未提供欄位與 null 不同。4. 可用 value_ref 時選定可見 table_id、row_id、field，由工具逐字搬移；工具不替模型選擇來源。5. 只有契約要求時才轉型或換算，選填欄位只依明示要求提供。6. 驗證工具結果是否完成原請求，最後依使用者格式與語言回答。

## Output Contract

回傳參數JSON物件供上層呼叫組裝，不能強迫最終答案只有物件。僅明確指定逐字的payload必須完全一致；其他自由文字依任務處理。缺資訊依上層輸出契約表示，calls-only可以是空陣列，不強迫自然語言錯誤。

## Failure

若缺少必填參數且無明確來源，立即中止並回報缺失欄位，不嘗試猜測預設值。若型別轉換失敗或枚舉值不在允許範圍內，回報具體衝突細節。

## Validation

同時核對 schema、實體與欄位語義、型別及單位。JSON 合法但綁錯來源或目的地仍不合格。
