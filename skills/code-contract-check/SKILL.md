## Use When

當需要驗證程式碼實作是否嚴格遵守預定義的輸入輸出契約，特別是在處理字串編碼、邊界值或需保持輸入資料原始狀態的場景時。

## Do Not Use When

僅排除非程式行為檢查且無契約定義的任務。允許就地修改的程式碼同樣適用，應檢查其是否符合允許範圍。

## Inputs

待驗證的程式碼片段、公開契約規格文件（包含型別定義、邊界條件、Unicode處理規則）、測試案例集（含預期輸出）。

## Procedure

1. 解析契約規格，提取關鍵約束：輸入型別、邊界值範圍、Unicode處理規則、輸入不可變性標記。2. 靜態分析程式碼，檢查型別註解與實際操作是否一致，識別可能修改輸入物件的語法結構。3. 針對邊界條件（如空值、極大/極小值、特殊Unicode字元）進行邏輯推演或模擬執行。4. 若具備執行環境，執行測試案例並記錄實際輸出與副作用；若無，僅基於靜態分析標記為「未動態驗證」。5. 比對分析結果與契約預期，標記不符項。6. 若未執行測試，明確標記為「未驗證」，嚴禁聲稱通過。

## Output Contract

依任務要求輸出檢查結果，可使用自然語言或指定 schema。不強制新增 JSON 欄位，需分清靜態審查與實際測試結果。

## Failure

若程式碼違反型別約束、修改了應為不可變的輸入、處理Unicode時丟失資訊或產生非預期亂碼、或邊界條件導致崩潰，則判定為失敗。若測試未執行卻聲稱通過，視為嚴重違規。

## Validation

檢查所有分析結果是否與契約預期一致；驗證輸入物件在執行前後狀態是否相同（若契約要求不可變）；確認Unicode字元處理後仍保持語義正確性；審查報告中是否誠實標記未執行項目。
